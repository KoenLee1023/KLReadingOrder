# KLReadingOrder 移行

> <span lang="ja">[English](../../README.md) · [简体中文](../zh-Hans/README.md) · [繁體中文](../zh-Hant/README.md) · [日本語](../ja/README.md) · [한국어](../ko/README.md)</span>

複数のフォント、文字サイズ、言語、横書き、縦書き、複数ページを含むテストデータを先に用意します。1枚のレシートだけに合わせ込まないでください。座標系を統一した後、変換層で候補を作成し、行の文字列、候補 ID、矩形、書字方向を旧実装と比較します。OCR と意味解析の処理は変更せず、パッケージと組み込み先アプリの回帰テストが通ってから旧並び替え処理を削除します。

## チェックリスト

- [ ] 同じページの矩形を、x は右方向、y は上方向へ増える共通の正規化座標へそろえます。
- [ ] OCR の認識結果から、安定した ID と元の並び順を持つ候補を作成します。
- [ ] 横書きまたは縦書きを指定するか、`.unknown` を使ってページごとに自動判定します。
- [ ] `candidateIDs` を使ってアプリ側の元データを参照します。文字間に空白を入れない場合は、空の `memberSeparator` を指定します。
- [ ] KLReadingOrder のパッケージテストを実行する
- [ ] 組み込み先アプリの回帰テストを実行する
- [ ] API リファレンスと変更履歴を更新する
