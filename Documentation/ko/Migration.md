# KLReadingOrder 마이그레이션

> <span lang="ko">[English](../../README.md) · [简体中文](../zh-Hans/README.md) · [繁體中文](../zh-Hant/README.md) · [日本語](../ja/README.md) · [한국어](../ko/README.md)</span>

여러 글꼴, 글자 크기, 언어, 가로쓰기, 세로쓰기, 여러 페이지를 포함한 테스트 데이터를 먼저 준비합니다. 한 장의 영수증에만 맞추지 마세요. 좌표계를 통일한 뒤 변환 계층에서 후보를 만들고 행 문자열, 후보 ID, 사각형, 쓰기 방향을 기존 구현과 비교합니다. OCR과 의미 분석은 변경하지 말고 패키지와 통합 앱의 회귀 테스트가 통과한 뒤 기존 정렬 코드를 삭제합니다.

## 체크리스트

- [ ] 같은 페이지의 사각형을 x는 오른쪽, y는 위쪽으로 증가하는 공통 정규화 좌표에 맞춥니다.
- [ ] OCR 인식 결과에서 안정적인 ID와 원래 입력 순서를 가진 후보를 만듭니다.
- [ ] 가로쓰기 또는 세로쓰기를 지정하거나 `.unknown`으로 페이지마다 자동 판정합니다.
- [ ] `candidateIDs`로 앱의 원본 데이터를 찾습니다. 글자 사이에 공백이 필요하지 않으면 빈 `memberSeparator`를 전달합니다.
- [ ] KLReadingOrder 패키지 테스트 실행
- [ ] 통합 앱의 회귀 테스트 실행
- [ ] API 레퍼런스와 변경 기록 업데이트
